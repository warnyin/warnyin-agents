# Proposal — publish-pack-polish

> what & why · scope in/out · alternative considered
> generated by DESIGN stage · single-writer (main loop) · gate ก่อน BUILD

## Context
ปิด 3 backlog item ที่ค้างจาก topic `project-memory` (entry #1, #2, #4) — ทั้งหมดอยู่ในผืนเดียวกันของ installer + pack gate + CLI help ที่ user-facing — รวมเป็น 1 topic ลด overhead ของ context profile (research→build) และหลีกเลี่ยงการเปิด topic ใหม่ 3 ครั้งสำหรับงานที่ verify gate เดียวกัน

## What
3 การเปลี่ยนแปลง (จาก `docs/backlog.md`):

### 1. EOL guard ระดับ tarball ใน `verify:pack` (#1)
- เพิ่ม pure fn ใหม่ `checkEol(entries /* {path, buf, ext} */)` ตรวจ CR (0x0D) ใน payload text files (Buffer-level `buf.includes(0x0D)` ไม่ decode UTF-8 — กัน multi-byte false-positive)
- ตรงกับ **KB #30** (rule.md §4) — บทเรียนจริง: `npm pack` แพ็คจาก working tree → checkout ที่เกิดก่อน `.gitattributes` ยังเป็น CRLF → installer copy แบบ byte ลง target → `/warnyin:build` ของผู้ใช้พังด้วย `script contains control characters` (KB TS-1 · project-memory)
- เทส EOL ที่ `src/` มีอยู่แล้ว (`src/tests/eol.test.mjs` — EOL1-EOL4) แต่ **ไม่ผูกกับ pack gate** — ปิดช่องว่างนี้
- **purity contract ของ `checkFiles` คงเดิม** (ไม่แตะ signature) — I/O แยกเป็น `readTextEntries(files, opts)` ที่รับ injectable `readFile`/`root` (pattern เดียวกับ `isEntrypoint`); path guards 3 ชั้น (absolute/../ /symlink); size cap 5 MB

### 2. `verify:pack` รันบน Windows dev ได้ (#2)
- `getNpmCmd(platform)` pure fn — Windows → `{ bin: process.execPath, prefix: [process.env.npm_execpath] }`; mac/linux → `{ bin: 'npm', prefix: [] }`
- KB #4: บน Windows `npm` ไม่อยู่ใน PATH ตรง (เป็น `.cmd` shim) → `execFileSync('npm')` → ENOENT
- **ไม่ใช้ `'npm.cmd'`** เพราะ CVE-2024-27980 — Node ≥20.12.2/22+ reject `.cmd`/`.bat` ด้วย `shell:false` (EINVAL) + PATH/CWD hijack ผ่าน unqualified binary name (supply-chain surface ก่อน publish)
- ใช้ `process.execPath` + `process.env.npm_execpath` (npm ตั้งให้เสมอเมื่อรัน `npm run verify:pack`) → spawn `node <npm-cli.js>` ล้วน ไม่ผ่าน shell ทุก platform
- ถ้า `npm_execpath` ไม่มี (รัน script ตรง) → exit 1 + error "ต้องรันผ่าน `npm run verify:pack`" (false-green guard)
- `main()` ส่ง `--ignore-scripts` กัน prepack lifecycle (defensive)

### 3. `cli.mjs --help` wording (#4)
- ปัจจุบัน wording "ไม่แตะ docs/" **ไม่ตรงข้อเท็จจริง**: `seedDocs()` รันทุกครั้ง (ทั้ง install และ `--update`) — แต่ `seedDocs` มี skip-if-exists ไม่ทับของเดิม → docs/ ถูก touch แต่ไม่ทับ
- แก้ wording ให้ตรง: "เขียนทับเฉพาะ CORE — `docs/` ถูก seed จาก template ถ้ายังไม่มี (ไม่ทับของเดิม)"
- **scope 5 จุด** (ไม่ใช่ 1): `src/bin/cli.mjs:50` (--help body) + `src/.warnyin/installer/templates/CLAUDE.md:49` (**payload** ผู้ใช้อ่าน) + `src/.warnyin/workflow/README.md:101` + `README.md:40` + grep `--update` ในทุกไฟล์ template `.md` (เพิ่มในขณะ BUILD ถ้าเจอ)
- **เพิ่ม regression guard**: spawn `cli.mjs --help` ใน `installer.test.mjs` → assert substring ใหม่ปรากฏ + substring เก่าหาย
- **เป็น fix wording** ไม่ใช่ behavior change — ไม่กระทบ semantics ของ installer

## Why
- **#1:** ปิด gate ลวง (rule §4 KB #30) — verify-pack เขียว = "ไม่มี leak" แต่ payload CRLF → user install แล้ว `/warnyin:build` พัง = **เคยเกิดจริง** ใน release 0.28.0 (CHANGELOG 0.28.0 Fixed)
- **#2:** dev Windows ไม่สามารถ verify ก่อน publish ได้ — gate silent fail เปิดช่องให้ regression เล็ดลอดขึ้น tarball
- **#4:** ผู้ใช้อ่าน `--help` → คาดว่า `--update` ไม่แตะ docs/ → รันแล้ว docs/ โดน touch → ความคาดหวังไม่ตรงความจริง (knowledge boundary ไม่ตรง — เคส rule §6 "ห้ามเดา")

## Out of scope (deferred-out → `docs/stages/<slug>/backlog.md`)
- EOL check ของ **install-time normalization** (installer normalizeEol) — มีอยู่แล้วใน `src/bin/cli.mjs` (`normalizeEol` per test.md) — ไม่อยู่ใน #1 (gate ก่อน publish ไม่ใช่ตอน install)
- CRLF cleanup ของ `docs/`/`src/` ที่ commit ปัจจุบัน — ใช้ `.gitattributes` (`* eol=lf`) + renormalize (`git rm --cached -r . && git reset --hard`) — ทำไปแล้วตอน 0.28.0 release (CHANGELOG 0.28.0 Fixed)
- `verify:pack` เพิ่ม fixture สำหรับ binary file detection — EOL check ต้อง skip binary (`.png`/`.ico`/...) — implement ในรอบนี้เลย (จำเป็นต่อ logic) ไม่ใช่ deferred
- Re-architect `verify-pack` เป็น multi-pass (allowlist/denylist/EOL แยกเฟส) — รอบนี้คง single `checkFiles` เดียว (ไม่จำเป็น + rule "minimalism" — YAGNI)
- Wording fix scope ขยายเกิน 5 จุดที่ design §Impact ระบุ — grep `--update` ในทุกไฟล์ `.md`/template ระหว่าง BUILD ถ้าเจอ statement "ไม่แตะ docs/" ที่ไม่ได้อยู่ใน 5 จุด → fix ในรอบนี้เลย (verified inline; ถ้าเยอะมาก → ตัดเป็น backlog entry ใหม่)

## Alternative ที่พิจารณา/ตัดทิ้ง
| option | เหตุผลตัดทิ้ง |
|---|---|
| แยก 3 topic อิสระ | overhead ของ DESIGN×3 + verify gate×3 + ceremony ซ้ำ — change ทั้ง 3 แตะ installer/verify-pack ผืนเดียวกัน (rule "กระทัดรัด" + "unify-in-place") |
| ใช้ third-party linter (markdownlint/eslint/prettier) ตรวจ EOL | ละเมิด rule §2 zero-dependency + มี gate เดิม (`eol.test.mjs` + เพิ่มใน `checkFiles`) ครอบอยู่แล้ว — เพิ่ม dep ไม่คุ้ม |
| ทำ EOL check เป็น shell script | rule §2 + §3 "npm scripts (dev tooling) ต้องเป็น node script cross-platform" — shell oneliner ผูก POSIX |
| `cli.mjs` rewrite help text เป็น template loaded จาก file | over-engineering — help text 1 ที่เปลี่ยน 5 คำ ไม่คุ้มแยก template (rule "minimalism") |
| ใช้ `npm run exec` หรือ `npx` แทน `'npm'` ใน Windows | over-engineering — แค่เปลี่ยน binary ตาม platform เลี่ยง spawn overhead ของ npx |

## Risks
- **EOL check false-positive ในไฟล์ที่มี CR legitimately**: กัน 3 ชั้น — (1) extension whitelist (`TEXT_EXT` import จาก `cli.mjs`) conservative skip (2) path guards (absolute/../ /symlink reject) (3) size cap 5 MB + warn (ไม่เงียบ)
- **EOL check fail ทั้ง `npm publish` และ CI `pack-verify`** พร้อมกัน (no env bypass โดยตั้งใจ): rollback ได้โดย revert เฉพาะบล็อก EOL check (logic แยกก้อน)
- **`npm_execpath` หายไป**: main() exit 1 + error "ต้องรันผ่าน `npm run verify:pack`" (false-green guard) — ไม่มี fallback เงียบ
- **wording fix ใน help text** ผู้ใช้ที่ pin version เก่าจะเห็น wording เก่า → ไม่กระทบ (help text ไม่ใช่ API contract)
- **`MIN_PASS` bump**: ตัวเลขผิดจะปลด anti-false-green gate ทั้งระบบ — Slice C ต้องอ่าน MIN_PASS ปัจจุบันจากไฟล์ก่อน bump (config-protection)
- **CHANGELOG Migration** มี `git reset --hard` (ลบงานค้างถาวร) — ต้องมี warning "commit/stash ก่อน" ใน CHANGELOG 0.29.1
